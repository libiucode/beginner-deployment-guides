# XGift Python 重写方案

日期：2026-10-11

## 目标与约束

从零建设用于 X Premium 礼品兑换的网站，部署到用户自己的 Windows 服务器。后端、兑换码、订单任务、赠送与付款流程全部使用 Python，不调用原项目 Go 程序，不迁移旧数据。浏览器仍使用必要的 HTML、CSS 和 JavaScript。

## 技术与部署

采用 Django 提供页面、管理功能和接口；SQLite 保存站点数据；独立 Python worker 串行处理持久化订单任务。网页进程由 Waitress 提供服务，绑定 127.0.0.1；Caddy 提供外部 HTTPS 访问。网站和 worker 作为两个 Windows 服务运行，提供 PowerShell 安装、启动、停止、备份脚本与环境配置示例。Windows 服务安装方式在实施计划中选定。

SQLite 采用短事务、忙等待和原子任务领取。网络调用不持有数据库写事务。首版定位单服务器部署；未来并发量增大时再迁移 PostgreSQL。

## 功能范围

- 公开兑换页：输入兑换码和 X 用户名、资格检查、兑换进度与结果查询。
- 管理后台：管理员登录、套餐配置、兑换码生成/导出/停用、批次文件夹、客户查询、统计和订单详情。
- 订单任务：资格核验、区域报价检查、创建付款链接、付款提交、结果查询、待核实处理。
- 人工处理：生成付款链接、单独补单、批量预览与确认、停止后续任务、历史记录。
- 公开付款链接：申请、持久化排队、取消和状态查询；接口不暴露其他客户订单。
- 配置管理：X 会话、商户、套餐、币种、预期金额、付款配置、HTTP/SOCKS 代理及节点池。
- 支持原项目使用的其他代理协议时，通过独立代理服务转换为 HTTP/SOCKS 出口；Python 网站不内嵌 Go 代理库。
- 提供模拟模式，用于不连接真实 X/支付服务的演示与自动测试。真实模式与模拟模式明确区分。

## 数据和安全

兑换码使用高熵随机值，查找使用摘要。为满足后台完整卡密查看与导出需求，另保存加密副本；完整值仅限授权管理员查看，不进入日志。

X 会话和敏感付款配置采用经过验证的加密库保存，主密钥独立于数据库并限制 Windows 文件访问权限。银行验证码与 CVC 不持久化；真实支付方式需在实现时确认其能否在此前提下完成流程。界面不暴露完整卡号。

采用 Django 会话认证、密码哈希、CSRF 保护、登录与兑换限流。状态查询使用兑换码或不可猜测访问令牌授权。记录管理操作与订单状态变化，日志屏蔽密钥和凭据。

## 订单与付款规则

订单状态包括排队、核验中、链接已创建、付款准备、付款已提交、成功、明确失败、待核实和取消。兑换码与客户绑定，并通过数据库事务阻止并发兑换。

付款前逐项核验商户、套餐、币种、金额及原订单付款状态。提交前持久化操作记录和稳定幂等键。连接中断、超时或重启发生在付款提交附近时，先进入待核实并查询原订单，禁止自动重新提交。不得承诺远端不支持幂等时可以保证严格恰好一次付款。

明确拒付与结果未知分开处理；禁止重试指令必须保留。人工补单先预览，确认后执行；失效链接替换必须保留原订单和核验依据。运行中的补单任务在重启后标记中断，不自动继续扣款。

网页和 worker 共用持久化付款锁及提交间隔。首版默认提交间隔至少 30 秒。节点轮换不得把未知付款当作失败后重新扣款。

## 外部接口边界

X 与支付集成封装为独立 Python 模块，以当前仓库源码作为行为参考。非公开接口、会话要求和支付验证可能变化，需要真实环境验证；模拟测试通过不代表真实赠送已可用。银行交互验证进入待人工处理状态，不能模拟成功。

研发、部署和测试默认不发起真实付款。真实赠送验收需要用户提供配置并明确指定测试订单和金额。

## 验证与交付

测试覆盖并发兑换、任务领取、金额/商户不匹配、付款提交超时、进程中断恢复、禁止重试、后台权限、CSRF 和模拟完整兑换。Windows 本地验证网站与 worker 启停以及持久化恢复。

交付 Python 项目、依赖声明、环境配置示例、Windows 部署与备份说明、测试结果，以及真实集成尚未验证的项目清单。真实接口无法验证时不得将其描述为已通过生产验收。

## 当前假设

按单台 Windows 服务器、单管理员起步；操作系统具体版本、域名和外网连通性在部署阶段确认。初始套餐及价格必须由配置提供并经远端核验，不能使用示例金额发起付款。
