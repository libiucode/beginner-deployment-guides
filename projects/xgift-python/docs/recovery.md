# 公开付款链接与人工补单

公开入口 `/links/` 为启用套餐创建不可猜测票据。票据令牌仅在申请时返回、浏览器会话保存，之后以 Authorization Bearer 查询或取消。内部兑换码加密保存并停用，不出现在兑换码列表、详情或导出中。公开队列即使在模拟模式也只生成链接，永远不自动确认付款。只有未被 worker 领取、未被补单接管的排队申请可取消。

客户点“我已付款，核实原会话”只排队只读检查。worker 用原会话进行 merchant/recipient/plan/amount/currency/session 绑定验证；证据不足转待核实。查询进度不访问远端，不会重新扣款。模拟链接不可实际付款。

具有 `gift.change_order` 的活跃后台员工可以在 `/operator/recovery/` 预览 1–100 个订单。预览有效期 10 分钟，记录冻结套餐、订单状态、原会话、付款尝试及全站配置摘要。开始前重新比对；开始只是持久化授权排队。停止不取消当前远端请求，只阻止后续订单。停止、中断批次所属订单不会被普通队列接着执行；须重新预览授权。

worker 通过 300 秒批次租约辨认中断：启动及后续循环只中断过期的运行批次，不干扰另一个 worker 的有效租约。硬退出后最多等待该租约过期才显示“已中断”；中断任务不自动继续付款。模拟进程异常即时记录中断。付款附近中断仍保留原提交标记、幂等键和全局付款锁，必须核实原订单。

`links` 始终不付款；`pay` 只用于模拟完整流程。真实批量付款被拒绝：当前 live provider 不持久化 CVC 或卡片，需通过已有 `pay_order` 命令对每个明确授权订单临时输入卡片。网页和常规 worker 不支持无人值守批量真实扣款。

明确失败的原订单只有同时具备持久化商户未扣款证据、人工确认以及执行时重新查询的明确失败/未扣款证明，才允许新建独立替换订单。永久禁止重试、未知结果、未释放付款锁、成功及取消订单禁止替换。原订单和原会话保持不变，审计保存原链接/会话、证明、操作者及替换订单；每个原会话最多三次。PaymentAttempt.no_retry 是原会话提交边界，retry_forbidden 才是商户永久重试限制，二者不可混用。

目前真实 Stripe 适配器没有提供明确失败同时未扣款的证明，因此真实失败链接替换会拒绝执行。这是尚未验证的真实接口能力，不以“可能未付款”猜测放行。新建链接附近丢失响应同样保留 checkout_creation_started 标记，不清除标记或盲目生成第二链接。
